### T7 发送链路改走队列（架构改造，最后做，独占 src/lib/queue、sender 核心与发送路由）
**目标**：回复/私信 API 从「同步直发」改为「入队异步发送」，让账号池轮换、日限额、熔断、Bull limiter、安全窗口真正生效。

1. **路由改入队**：`src/app/api/comments/[id]/reply/route.ts`、`[id]/dm/route.ts`、`batch/reply/route.ts`、`batch/dm/route.ts` 改为调用 `addReplyJob`/`addDmJob`（`src/lib/queue/index.ts:505,523`），返回 202 `{ queued: true }` 语义。鉴权、归属校验、配额检查（checkPlanLimit）、模板/合规校验仍在路由内同步完成，失败仍同步报错；只有「发送」动作异步化。
2. **前端适配**：comments 页发送成功提示改为「已加入发送队列」语义；相关失败分支（502 FAILED 死代码）按新响应清理。
3. **幂等**（P1-5）：`processSendJob` 发送前检查该 comment 是否已有同类型 SENT 记录，有则短路跳过；失败记录改为复用/更新同一 Reply/Dm 行而非每次 create。
4. **配额口径**（P1-2）：`src/lib/plans/index.ts` 用量统计从「数 Activity」改为「数 Reply/Dm 表今日 SENT 记录」；批量入队后每条成功发送由 processSendJob 落 Reply/Dm 行，口径自然准确。路由内不再按批次只建 1 条 REPLY_SENT Activity（改为入队动作本身的 Activity 或去掉，保持 dashboard 动态页合理即可）。
5. **原子化**（P1-10）：`account-pool.ts` 的 `handleSendFailure`/`handleSendSuccess` 读改写改为原子操作（`decrement/increment` + 边界钳制），`pickAccount` 的额度占用改为 `updateMany` 条件原子认领（`where dailySent < dailyLimit` 且状态可用），认领失败换下一个账号。
6. **consecutiveFailures 语义**（P1-7）：`src/lib/scraper/index.ts` 只在 Bull 最终失败（`job.attemptsMade === job.opts.attempts - 1`）时递增，避免单周期内重试把视频打成 ERROR。
7. **测试**：更新/新增 process-send-job、account-pool、路由入队、幂等、配额口径用例；既有相关测试按新行为调整（这是本任务允许改既有测试的唯一场景，逻辑变化导致的必要适配）。
8. 注意 `sender/providers/douyin.ts` 归 T6，不要改它。
